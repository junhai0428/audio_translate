# 第 1 步 · 人声分离

## 干什么

把一条**已提取好的音频**拆成「纯口播人声」和「纯 BGM/伴奏」两条轨。你是整条链的地基——你交的东西不干净，后面转写全盘皆错。

## 在链路中的位置

```
源音频 → 【第 1 步 人声分离】 → 第 2 步 语音转写 → 第 3 步 翻译控长 → 第 4 步 配音对齐 → 越南语配音轨
```

## 工单输入

- 音频文件绝对路径（mp3 / wav / m4a / aac / flac / ogg）
- 工单目录 `work/<音频名>/`
- 特殊要求（如"前 30 秒是广告口播，重点是它"）

> **不做视频抽轨**：音视频分离由用户侧工具完成，交给你的就是音频。收到视频文件请退回上游，不要自己转（会引入二次编码，且不在本链路职责内）。

## 你必须产出

| 文件 | 要求 |
|---|---|
| `<工单>/01_separate/<名>.mp3` | 纯人声，去伴奏、去底噪残留，192kbps，时长 = 源音频 ±0.2s |
| `<工单>/01_separate/<名>_bgm.mp3` | 纯伴奏；若原音频无 BGM 则生成等长静音 |
| `<工单>/01_separate/report.json` | `{src, duration, vocal_duration, bgm_duration, method, warnings[]}` |

## 技术路线（可自行优化）

1. ffmpeg 统一解码成 44.1k 立体声 wav（`-vn -ac 2 -ar 44100 -c:a pcm_s16le`；带 `-vn` 是为了万一误传视频也能解出音轨，但正常输入应是音频）。
2. demucs 两轨分离：`--two-stems=vocals -n htdemucs --other-method minus -d cuda`（**必须走 GPU**；本机 RTX 3060 + torch 2.14.1+cu130。只有确认无可用 GPU 时才退回 `-d cpu`）。
3. 人声轨编码 mp3 192k；`no_vocals` 编码 BGM。
4. 分离后抽检：人声轨能量分布、是否有音乐旋律残留、是否削波。

## 验收清单（自检通过再交）

- [ ] 两文件时长与源音频差 ≤ 0.2s，ffprobe 可读
- [ ] 人声轨时长内 F0 有效帧占比 > 25%（说明真有人说话）
- [ ] 人声轨峰值 ≤ -0.5dBFS，无削波
- [ ] 人声轨里听不到伴奏旋律（抽前/中/后 3 段各 5 秒）
- [ ] 若判定"整段无人声"，明确上报，不要交空轨糊弄下游
- [ ] 不做额外降噪/美颜，过度处理会伤转写

## 打回条件

第 2 步反馈"识别不出内容/识别出歌词/大面积乱码"，即视为你未分离干净，需换 `--shifts 2`、`--overlap 0.5` 重做或改用 `mdx_extra` 模型。

## 参考实现

`pipeline/separate.py`。实测（本机 RTX 3060）：59s 音频 **6.9s**、40s 音频 5.7s、21s 音频 4.8s，约 **0.1 倍实时**；
CPU 路线是 65s 音频 141 秒（约 2.2 倍实时），慢 20 倍。

> **必踩的坑**：不设离线时 demucs 每次启动都会去 huggingface.co 校验模型，国内网络超时重试要 60~90 秒，
> 会让人误以为"GPU 没生效"。`run.py` 已按 `config.json` 的 `hf_offline` 注入 `HF_HUB_OFFLINE=1`，别去掉。
